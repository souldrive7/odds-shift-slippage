# Dead-label survey: what per-label calibrators do when one class is absent from the calibration window

Date: 2026-09-07. Scope: per-label (one-vs-rest) calibration in multi-label top-K ranking; the
question is what an implementation returns for a label whose calibration split contains only one
class (typically zero positives, a "dead label").

Classification key: **(a)** IDENTITY pass-through (raw score returned unchanged) / **(b)** CONSTANT
(0, class mean, prior, ...) / **(c)** EXCEPTION or refusal / **(d)** not applicable (no per-label
calibrator) / **(e)** could not determine.

Method: primary sources only. scikit-learn was read from the installed package in this repo's venv
and exercised empirically; every other library was shallow-cloned (or, for netcal, downloaded as the
PyPI sdist) into the session scratchpad and grepped with line numbers. Line numbers refer to the
commit / version stated in the table. Web pages were fetched with WebFetch; Kaggle discussion pages
and the Wayback Machine could not be fetched (see section 2).

## 4. Verdict

Across 17 implementation rows in 11 code bases, **exactly one library exhibits an identity pass-through** — MAPIE's `TopLabelCalibrator` (`mapie/calibration.py` L388-395), and even there it is (i) top-label rather than one-vs-rest calibration, (ii) triggered by "label never predicted as top-1 on the calibration set" rather than "label has zero positives", and (iii) accompanied by a `warnings.warn`. Every genuine one-vs-rest calibrator examined either returns a **constant** for a single-class window (scikit-learn isotonic and Platt, and everything built on them: netcal, PyCalib, torch-uncertainty; PyCalib's `OneVsRestCalibrator` and netcal's one-vs-all helper do this deliberately with a warning) or **raises** (any `LogisticRegression`-based calibrator: sklearn, PyCalib, betacal; and I-Max class-wise binning, whose KDE step fails on an empty positive set). Of the **two public reference implementations** from the calibration papers checked (Ullah et al. 2025; Patel et al. 2021), **zero** have an identity pass-through: Ullah et al. fit one map shared across all labels, and I-Max CW raises. Of the Kaggle Santander solutions that could be verified (2nd, 3rd, 8th-reproduction, 21st, common kernels), **zero** calibrate per product; dead products are excluded or floored at a hand-set constant, and the 1st-place write-up could not be retrieved. Finally, no paper was found that names or measures the phenomenon of uncalibrated (identity) labels dominating top-K; the only primary-source acknowledgement of the underlying failure is the scikit-learn user guide's "fit on data with no positive class ... results in ineffective calibration". The identity fallback therefore has to be presented as a property of the experiment's own calibration wrapper (or of ad-hoc code that guards `len(np.unique(y)) < 2` by returning the raw score), not as the default behaviour of any widely used library.
